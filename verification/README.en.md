# Per-file execution reports

[中文](README.md) · English

This directory preserves real vendor API attempts made by the [file executor](../tests/run_example_files.py). It does not retain keys, request messages, response text, reasoning text or raw errors. Use [current example status](../en/docs/example-status.md) to determine which files have complete valid evidence, rather than adding up historical `passed` strings.

Each attempt has its own report; normal new executions do not overwrite existing outcomes. Execution times and durations have been removed under the [privacy policy](../en/docs/evidence-policy.md#minimize-execution-time-information-project-rule), with a random `evidence_id` identifying evidence. Existing paths and Git history are unchanged. `source_sha256` binds the executed file and supporting dependencies, `requests` contains real HTTP metadata and `exit_code` records the original program's result. A pass covers that execution, model, parameters and input branch only. It does not guarantee future availability, universal accuracy, all optional inputs or arbitrary generated combinations. [Execution and classification](../tests/run_example_files.py) · [Evidence policy](../en/docs/evidence-policy.md)

## Interpreting historical reports

- Early `attempt1` observation did not decompress some HTTP responses; some Shell/TypeScript records also had process-only evidence. The original scripts did run, but some `passed` results lack complete HTTP completion/content metadata and are not valid current release evidence. Some `failed` entries in later `attempt2` reports similarly reflect observation gaps, not failure of the original script or lack of provider capability. Inspect the original `exit_code` to distinguish them. [Early DeepSeek report](examples/2026-10-14-deepseek-attempt1.json) · [FIM retry](examples/2026-10-14-deepseek-fim-attempt2.json)
- Later reports observe independently decompressed copies for statistics while forwarding the actual bytes unchanged to the SDK. Python, Node and cURL all require real request metadata. Release checks revalidate old records using current rules rather than trusting historical state strings. [Executor](../tests/run_example_files.py) · [Node observer](../tests/live_fetch.mjs) · [cURL observer](../tests/live_curl.py) · [Release check](../tests/check_example_release.py)
- One MiniMax stream returned nonempty final text, `finish_reason=stop`, usage and actual transport EOF, without `[DONE]`. This records that execution, not a universal protocol guarantee. Acceptance requires explicit normal completion and either the stream's termination event or actual transport exhaustion; a closed connection alone is insufficient. [Observed run](examples/2026-10-14-minimax-stream-attempt4.json) · [Classification tests](../tests/test_live_example_runner.py)
- Zhipu HTTP 429 does not establish authentication failure or an unsupported feature. The observed `1305` is officially defined as model overload; `1302` is an account rate limit. Do not infer which one occurred from HTTP 429 alone. [Official error codes](https://docs.bigmodel.cn/cn/api/api-code) · [Recorded stream attempt](examples/2026-10-14-zhipu-stream-attempt3.json)

Images use generated red PNGs; Kimi video uses a locally generated short red video; Doubao video uses public teaching material from the [official video guide](https://docs.volcengine.com/docs/ark/video-understanding?lang=zh). No private user photos or videos were read. A normal file pass is not an image-recognition accuracy test. Example tools use local simulated data; real API calls do not turn the weather, orders or inventory into real business data.
