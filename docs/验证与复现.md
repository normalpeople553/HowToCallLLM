# 验证与复现

[English](../en/docs/verification.md)

本页定义安装、公开离线检查和本地真实验证流程；命令、退出码与报告字段由[统一验证器](../tests/provider_verify.py)、[逐文件执行器](../tests/run_example_files.py)和[锁定依赖](../requirements-lock.txt)实现。参数解释另见[调参导航](参数说明与调参.md)，证据边界见[来源规则](来源与核验规则.md)。

## 可复现环境

在仓库根目录使用 Python 3.10+ 创建独立环境，安装完整锁定依赖。私有实测资料不随仓库下载提供，公开离线检查不需要它们。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
python -c 'import sys, openai; print(sys.version); print(openai.__version__)'
```

Windows PowerShell 激活环境的命令是 `.venv\Scripts\Activate.ps1`。仓库的 [CI 模板](../ci/offline-checks.yml)定义 Linux/Windows 与 Python 3.10/3.13 的检查矩阵，当前尚未启用 GitHub Actions。模板不等于对应平台已通过。

## 离线检查

以下命令不读取 API Key，不发送模型请求；测试使用模拟响应覆盖空流式块、截断、工具参数和结果回传等边界。

```bash
python -m unittest discover -s tests -p 'test_*.py'
python skills/model-manual/scripts/sync_verification.py --check
python skills/model-manual/scripts/example_catalog.py --check
python skills/model-manual/scripts/model_catalog.py --check
python scripts/render_human_examples.py --check
python tests/check_example_release.py --check
```

具体功能例子见[官方示例索引](官方示例索引.md)。每个型号的 `examples/sources.json` 维护出处与运行方式；修改清单后运行 `python skills/model-manual/scripts/example_catalog.py --write-index` 更新派生索引。离线 mock 不发送请求；直接运行示例则会真实调用，上传类示例还会发送输入文件。历史统一验证器只覆盖自身测试项，不自动执行所有进阶文件；完整文件另见[调用代码目录](示例实测状态.md)。

## 语言模型清单维护（不发请求）

[六家清单](model-lists/README.md)由 `data/model-lists/<vendor>.json` 生成；先核对官方 API ID、生命周期、模态和定价入口，复核中英说明及范围，再执行：

```bash
python skills/model-manual/scripts/model_catalog.py --write-pages
python skills/model-manual/scripts/model_catalog.py --check
python skills/model-manual/scripts/model_catalog.py --vendor deepseek --model deepseek-v4-pro
```

`--write-pages` 同时生成两语的总目录和六家清单，`--check` 检查全部派生页是否过期；筛选查询不能与页面操作混用。未命中的准确 ID、清单结构或现有证据校验失败、过期页面均退出 `2`，成功退出 `0`。查询读取官方资料快照与已登记代码，不读取 Key、不访问网络、不做在线模型清点。资料来源必须是对应厂商的允许官方 HTTPS 域名；校验域名与结构不等于事实语义已经自动核实。

新增清单不更改默认卡片或示例源码；需要完整接入说明时再单独增加准确型号卡片、参数及真实运行过的示例。现有示例文件的通过不会转移给新列出的型号。[证据边界](来源与核验规则.md)

## 人类篇代码阅读页（不发请求）

[代码阅读与人工核对](../human/examples/README.md)直接展示六个维护型号基础文件的完整代码。修改调用后维护者仍须验证；生成器按公开源码、准确型号与关键行锚点生成两语页面，不读取私有报告，不创建新调用代码，也不会重新发请求。

```bash
python scripts/render_human_examples.py --write
python scripts/render_human_examples.py --check
```

不带参数时默认只读检查。源码、准确型号或关键行不匹配、页面过期均退出 `2`，检查或写入成功退出 `0`；`--write` 只更新 `human/examples/` 的14个阅读页。中英代码块与实际源文件保持一致，解释来自同一组双语阅读提示；修改调用字段或提示词的 Agent 实现仍须另行验证。源码和支持依赖的证据规则见[来源规则](来源与核验规则.md)。

## 本地真实验证

调用代码需要维护者实际运行后再发布；过程记录仅保存在本地，不输出到公开目录。统一验证器检查固定能力项，逐文件执行器运行已登记原文件；二者不互相继承结果，缺记录不等于通过。公开 `private` 标记不等于未执行或公开通过证明。[发布规则](来源与核验规则.md)

## 统一验证器：固定能力项

只给准备验证的厂商配置环境变量，或在被 Git 忽略的根目录 `.env` 中填写；缺少 Key 的厂商记为跳过。完整测试会产生真实 API 请求。[项目 Key 规则](来源与核验规则.md)

```bash
# 环境变量中的 Key 不会写进报告
python tests/verify_calls.py kimi qwen --report /tmp/model-manual-verification.json

# 保留单型号入口
python tests/verify_kimi_k2_6.py --report /tmp/kimi-k2.6-verification.json
python tests/verify_deepseek_flash.py --report /tmp/deepseek-flash-verification.json
```

`/tmp/` 是 macOS/Linux 示例；Windows 可改成临时目录内的路径。默认拒绝覆盖已有报告，确实需要替换时显式使用 `--overwrite`。新报告默认保存到被 Git 忽略的 `.local/evidence/`；也可显式指定仓库外的本地路径。报告、回复、统计和执行哈希不提交 GitHub，公共卡片不填写报告路径。

报告自动记录运行环境、代码提交与未提交改动标记、接口地址、实际使用的安全参数、结束原因、token 数和分类结果；不保存 Key、问题正文、模型回答、思考正文、工具参数或请求 ID。错误只保存类别与允许的业务码，不直接落盘厂商原始错误文本。[实现与字段](../tests/provider_verify.py)

验证层次由测试项说明：普通与 JSON 检查正常结束和可解析结果，工具测试执行模拟天气闭环，图片测试识别生成图片的颜色；一次通过只证明该固定样例，不代表通用准确率或其他型号能力。[验证脚本](../tests/provider_verify.py)

### 统一验证器退出码

| 退出码 | 含义 |
|---|---|
| 0 | 所选测试全部通过 |
| 1 | 至少一项失败 |
| 2 | 有限流或跳过，且没有失败；或命令参数/报告路径不合法 |

限流、鉴权失败、截断和断流单独分类；不要把“没有抛出异常”当成通过。[分类实现](../tests/provider_verify.py)

## 逐文件执行：原始示例与真实网络旁观

默认只列出清单，不读取密钥、不发送请求；`--vendor` 或 `--file` 可筛选已登记文件。[参数实现](../tests/run_example_files.py)

```bash
python tests/run_example_files.py --vendor minimax
python tests/run_example_files.py --file models/deepseek/deepseek-flash/examples/10_vision_files.py
```

**只有下列显式 `--execute` 命令才执行真实调用，可能计费并上传输入。** 使用自己有权发送的素材；不要把私有照片或业务文件误当测试 fixture。本项目执行器生成本地教学图片，视频输入依运行环境与显式参数决定，具体要求以文件来源清单和执行器为准。[输入准备实现](../tests/run_example_files.py)；[官方示例索引](官方示例索引.md)

```bash
python tests/run_example_files.py --execute --vendor minimax \
  --report /tmp/model-manual-minimax-files.json

python tests/run_example_files.py --execute \
  --file models/deepseek/deepseek-flash/examples/10_vision_files.py \
  --report /tmp/model-manual-deepseek-file.json
```

报告路径必须是新路径，不覆盖旧证据；报告以随机 UUIDv4 `evidence_id` 标识，不保存测试日期、时间戳和运行耗时；每项记录原文件与帮助文件指纹、运行状态，以及实际获得的接口、参数、结束原因、用量等白名单元数据。旁观器不保存 Key、消息、回答/思考正文、原始错误或请求/工具 ID；也不替换厂商响应。源码变化与旁观证据缺失不能靠旧进程成功记录补齐。[执行器](../tests/run_example_files.py)；[Node 旁观器](../tests/live_fetch.mjs)；[cURL 旁观器](../tests/live_curl.py)

TypeScript 示例还需 [package.json](../package.json)规定的 Node.js 环境与 [package-lock.json](../package-lock.json)锁定依赖，可在仓库根目录运行 `npm ci` 安装；Shell 示例需要 Bash、cURL 与 Python。缺依赖、缺输入、超时或限流会保留为对应状态，不因为未完成就推断模型不支持。[运行环境检查](../tests/run_example_files.py)

Kimi 本地视频 fixture 需要可用的 `ffmpeg`；豆包视频需显式传入获准公开 HTTPS 素材，例如官方教程中的测试地址。执行器不会继承环境里私有的图片/视频地址。[输入准备实现](../tests/run_example_files.py) · [豆包官方教程](https://docs.volcengine.com/docs/ark/video-understanding?lang=zh)

```bash
python tests/run_example_files.py --execute --vendor doubao \
  --video-url https://ark-project.tos-cn-beijing.volces.com/doc_video/video-understanding.mp4 \
  --report /tmp/model-manual-doubao-files.json
```

逐文件执行器退出 `0` 仅表示这次选中的文件均通过它的检查，否则退出 `1`；命令参数非法可退出 `2`。查看状态、真实请求和报告的具体范围，不能只引用退出码。[判定与退出实现](../tests/run_example_files.py)

文档内代码块和生成器任意输出组合不在这份逐文件结论内；更改提示词、预算、思考开关、输入素材或调用协议后，要验证更改后的路径。实测中使用的天气、订单、库存等模拟工具数据也不等于真实业务验证。[证据规则](来源与核验规则.md)；[参数说明与调参](参数说明与调参.md)

### 文件级发布门槛

[发布检查](../tests/check_example_release.py)默认只生成或检查公开调用代码目录，不读私有记录、不计算实测哈希、不发送请求；显式 `--require-passed` 才核验本地报告与当前源码的完整 HTTP、正常结束和非空正文。没有本地记录不会补成通过。[本地说明](../verification/README.md)

```bash
python tests/check_example_release.py --write
python tests/check_example_release.py --check
python tests/check_example_release.py --check --require-passed
```

`--check` 只保证公开代码目录同步，不要求私有报告；`--require-passed` 单独核验维护者本地证据，未满足退出 `1`，页面过期或资料结构错误退出 `2`。此结果只在本地查看，不写入公开页面。[判定实现](../tests/check_example_release.py)

## 双语同步与译文复核

中英文共用官方型号卡片、调用源码和来源清单，不为翻译重新发起 API 调用。以下生成命令现在同时处理两种语言，检查命令也会检查两种语言是否过期；它们不读取 Key、不发送请求。

```bash
python skills/model-manual/scripts/example_catalog.py --write-index
python skills/model-manual/scripts/model_catalog.py --write-pages
python scripts/render_human_examples.py --write
python skills/model-manual/scripts/sync_verification.py
python tests/check_example_release.py --write
python scripts/check_translations.py --check
```

静态译文的维护位置见[对应清单](../en/translations.json)。中文正文更新后先复核英文的字段、范围、未知项、生命周期及来源，再更新清单里的源文件哈希；可用 `python scripts/check_translations.py --fingerprint docs/来源与核验规则.md` 只读查看已复核页面的当前哈希。工具不会自动替你宣称语义审校完成。[双语规则](来源与核验规则.md)

## 同步能力摘要

公开厂商摘要与验证说明只从型号卡的官方来源及发布边界生成，不读取私有报告。修改官方事实后运行：

```bash
python skills/model-manual/scripts/sync_verification.py
python skills/model-manual/scripts/sync_verification.py --check
```

脚本不发请求，不读取本地实测，不输出统计或报告链接，也不把维护记录推广为厂商能力承诺。查看[官方依据与本地验证说明](验证状态.md)和[调用代码目录](示例实测状态.md)。
