## 项目建议：一次只改一个问题

1. 先选准确型号与端点，再阅读该文件的参数映射。标为未知的默认值或语义保留未知，不用同厂新型号或别家同名字段补齐。[来源规则](来源与核验规则.md)
2. 先保留示例请求跑通，再根据任务分别调整提示词、输出预算、思考配置或采样；调整后重新检查结束状态与正文，不把旧结果当成新参数的证明。[验证与复现](验证与复现.md)
3. `temperature` 和 `top_p` 讨论的是采样，不是“准确率百分比”。某些型号固定或忽略部分采样字段，先查本型号限制，再决定能不能调；不要把“更发散”说成“更正确”。[DeepSeek 采样解释](../models/deepseek/deepseek-flash/parameters.md#sampling)、[Kimi 参数](../models/kimi/kimi-k2.6/parameters.md)
4. 把上下文窗口与单次生成预算分开规划，遇到 length、空正文、无结束标记时先看实际用量与模式；增加预算不是解决所有错误的通用方法。[DeepSeek 预算解释](../models/deepseek/deepseek-flash/parameters.md#budget)、[MiniMax 预算解释](../models/minimax/MiniMax-M2.7/parameters.md#budget)、[生产检查](06-真实踩雷与生产检查.md)
5. 需要机器处理时明确 JSON/Schema 或工具协议，并执行本地校验；不要用低温度代替输出结构与业务验证。[六家文件索引](官方示例索引.md)、[工具与 JSON 检查](06-真实踩雷与生产检查.md)
