# 来源与核验规则

[English](../en/docs/evidence-policy.md)

本项目把信息分成三类；这是仓库的编辑规则，规则本身以本文件为准。

- **官方**：模型名、接口地址、参数行为、价格、额度和生命周期等厂商事实，必须在同一段、同一表格行或紧邻位置链接厂商官方文档。
- **实测**：必须给出测试日期，链接脱敏报告及报告中登记的测试脚本；它只证明当时、该账户、该模型和明确测试范围内的结果。脚本自动生成报告的方法见[验证与复现](验证与复现.md)。
- **项目约定**：选型、默认值、安全习惯和排查顺序等编辑判断，必须明确写成“项目建议”或“项目规则”，不能伪装成厂商承诺。

价格和免费额度变化快。本项目不把手抄价格数字当作长期真源，而是直接链接官方页面：[DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/)、[Kimi](https://platform.kimi.com/docs/pricing/chat)、[智谱 GLM](https://docs.bigmodel.cn/cn/guide/start/pricing)、[通义千问](https://help.aliyun.com/zh/model-studio/model-pricing)、[豆包方舟](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh)、[MiniMax](https://platform.minimax.cn/docs/guides/pricing-paygo)。

## 付费型号选型（项目规则）

本项目的厂商默认型号、维护示例和默认生成代码全部使用付费型号；不以省钱为由选择免费型号，也不在失败后静默回退到免费型号。每张维护型号卡的 `billing.type` 记录 `paid` 并引用官方定价来源，厂商目录的 `selection_policy` 记录这项项目规则。赠送额度或余额抵扣不改变型号按量计费的性质；`Flash` 名称本身也不表示免费。具体价格仍只认上面的官方页面，不保证付费型号没有限流。

2026-10-14 起，智谱维护目标由免费 `glm-4.7-flash` 改为同代付费 `glm-4.7`；旧报告原文保留，仅供历史排错，不作为新型号通过证据。[智谱官方定价](https://docs.bigmodel.cn/cn/guide/start/pricing) 用户明确指定其他型号时，按准确 ID 核实并说明与当前收录范围的差异，不能把名字改成已收录型号后冒充执行成功。

## 双入口与事实维护

项目首页分别导航至[人类篇](../human/README.md)和[Agent 篇](../agents/README.md)，Agent 的执行入口仍是 [SKILL.md](../skills/model-manual/SKILL.md)。两篇共享事实与证据，只在导航和任务说明上区分；人类教程按需查阅，不要求 Agent 顺序读取。

### 双语维护（项目规则）

中文与英文分别提供人类篇、Agent 篇、通用指南、型号说明书和参数页，但共用机器卡、示例代码及原始报告。翻译不改变模型 ID、API 区域、请求参数、提示词或验证状态；如需改调用代码，按原有真实验证规则处理，不能借翻译沿用旧证据。

[翻译清单](../en/translations.json)记录静态页面对应关系与已人工核对的中文源文件哈希；源文变更后，[翻译检查](../scripts/check_translations.py)会要求复核英文，同时检查官方外链和参数页的示例文件映射。哈希仅标记待复核版本，不证明译文语义一定正确；不能未读译文就盲改哈希消除报错。

两个语言的示例索引、逐文件状态和历史型号状态由各自生成器从同一事实与报告派生；生成/检查命令同时处理两语。译文不另建英文模型卡、示例或实测报告，不因翻译改动源码路径；型号迁移则使用新路径并重新验证，保留旧报告。[同步与复现](验证与复现.md)

模型级机器事实保存在 [`skills/model-manual/references/models/`](../skills/model-manual/references/models/)；[`vendors.json`](../skills/model-manual/references/vendors.json)只负责厂商入口、默认型号和兼容摘要。型号的参数约束优先于厂商摘要，未知型号不能自动继承默认型号的思考开关。

### 型号发现清单（项目规则）

发现清单的每个准确 API ID 都有官方型号、价格入口和补充来源，记录核对日期及中英说明；不把价格表残留、开源权重名或订阅简称直接当成当前可调用 API。已下线型号不列入来源清单、双语页面或 Agent 查询；历史测试报告保留，不因目录清理删除或改写。仍接受请求的兼容别名与未来才下线的型号可保留，但须说明重路由或截止条件。其余区分官方列出、预览、仍可用旧版、别名和可用性待确认，具体限制以逐行来源为准，不宣称穷举所有地区、账户或历史版本。免费型号可以出现在发现清单，但不改变维护示例和默认生成代码的付费规则。

发现层不保存人工填写的“实测通过”或卡片路径。[查询工具](../skills/model-manual/scripts/model_catalog.py)按准确厂商与 ID 从维护卡片及当前源码逐文件报告派生仓库覆盖；别名/同系列不能继承。新增发现条目不要求伪造详细卡片或发起测试；要新增调用示例时仍遵循下面的来源、参数及真实执行规则。维护方式见[验证与复现](验证与复现.md)。

### 官方示例收录规则（项目规则）

基于官方文档写的代码标为 `adapted_from_official`，不称为官方原版；清单列出准确 Model ID、功能、官方页面、核对日期、必需环境变量、运行命令和项目改写。模拟数据、校验与循环上限属于项目补充，不当成厂商要求。厂商样例换成新型号时，先找当前收录型号的明确支持依据，不直接换名套用。

文件的 `verification.offline` 与 `verification.live` 分开记录。`live=not_run` 表示清单未登记真实执行证据；任何非 `not_run` 状态都必须引用实际逐文件报告，校验型号、状态、时间、源码及支持文件指纹。`passed` 还要求当前型号最后一次真实 HTTP 请求正常结束且正文非空；流式须有终止事件或实际传输 EOF，不能只凭退出码。具体校验见[清单脚本](../skills/model-manual/scripts/example_catalog.py)。历史型号通过不能自动填成新文件通过；后续报告与清单须按[逐文件状态](示例实测状态.md)核对。离线 mock 只证明模拟场景，不证明真实 API 接受请求或结果可靠。未集成项列出原因与官方依据，不把“未写示例”解释为“不支持”。维护命令见[验证与复现](验证与复现.md)。

新增或更新型号身份、能力和通用参数时先修改准确型号卡片及来源，再更新受影响的示例和人类解释；功能示例的出处与改写记录维护在该型号的来源清单中。更新统一验证器证据时新增报告、更新卡片指针并运行同步脚本；更新逐文件证据时保留新的原始报告及源码指纹，按[示例实测状态](示例实测状态.md)核对当前文件。不要手改派生能力摘要，也不要用编辑日期覆盖测试时间。六家[参数说明](参数说明与调参.md)是人工解释，需同时核对卡片、实际代码与官方来源。

## 能力状态与验证证据

统一验证器派生的 `verified`、`documented` 和 `unknown` 分别表示对应测试项通过、只有官方依据而无该项通过证据、没有可靠结论。它们须连同[历史统一流程状态](验证状态.md)的日期与范围阅读；不等于所有示例文件的实时状态。`unknown` 不等于不支持。[同步实现](../skills/model-manual/scripts/sync_verification.py)

官方说明与实测结果分别记录：官方链接支持能力声明，报告支持具体运行结果。一次限流不会改写成“模型不支持”；一次请求被接受也不等于完整工具流程、输出边界或图片内容识别已经验证。

型号卡片的 `verification=null`、`verification_scope=not_run` 表示尚无该卡片登记的**统一验证器报告**，不表示逐文件执行器从未调用该型号；MiniMax 等型号须同时查[示例实测状态](示例实测状态.md)。不创建空成功报告，不继承其他型号证据；报告路径非空但文件不存在属于校验失败。[同步实现](../skills/model-manual/scripts/sync_verification.py)

旧版报告只检查非空正文、首段工具参数或图片请求格式，保留为历史基础验证；没有记录的 `finish_reason` 和完整闭环结果不得补写成通过。新版本严格验证报告由脚本写出实际 SDK 版本、代码版本、安全参数、结束原因和分类结果；事实变化通过新增报告保留时间线。[历史报告示例](../models/kimi/kimi-k2.6/verification/2026-10-13.json)

逐文件执行器运行原文件，并旁观真实网络传输，不用模拟响应替换厂商结果；报告只保存白名单元数据。判定需结合文件自身校验、实际请求与正常结束，不仅看进程退出码。失败、限流、缺输入、缺运行环境或证据缺口都应保留，不承诺整份清单全部成功。[执行器](../tests/run_example_files.py)；[逐文件状态与报告](示例实测状态.md)

所有当前可执行示例具备完整通过证据之前，不宣称“全部实测成功”。[发布检查](../tests/check_example_release.py)的 `--check` 只检查状态页同步；必须加 `--require-passed` 才会将未通过项作为发布门槛失败。早期观察范围差异与历史报告保留规则见[报告说明](../verification/README.md)。

说明性代码块、生成器输出及自行更改后的输入/参数组合，不继承旁边链接文件的通过结论；源码、帮助文件、运行环境或参数变化后，应重新执行相应路径。工具数据明确是模拟时，即便真实模型闭环通过，也不能称为真实业务或实时天气验证。以上是项目证据规则，具体参数解释见[调参导航](参数说明与调参.md)。

本仓库要求 Python 3.10+，可复现环境使用[锁定依赖](../requirements-lock.txt)。正常安装、离线校验和真实 API 验证命令见[验证与复现](验证与复现.md)。
