# 来源与核验规则

本项目把信息分成三类；这是仓库的编辑规则，规则本身以本文件为准。

- **官方**：模型名、接口地址、参数行为、价格、额度和生命周期等厂商事实，必须在同一段、同一表格行或紧邻位置链接厂商官方文档。
- **实测**：必须给出测试日期，链接脱敏报告及报告中登记的测试脚本；它只证明当时、该账户、该模型和明确测试范围内的结果。脚本自动生成报告的方法见[验证与复现](验证与复现.md)。
- **项目约定**：选型、默认值、安全习惯和排查顺序等编辑判断，必须明确写成“项目建议”或“项目规则”，不能伪装成厂商承诺。

价格和免费额度变化快。本项目不把手抄价格数字当作长期真源，而是直接链接五家的官方页面：[DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/)、[Kimi](https://platform.kimi.com/docs/pricing/chat)、[智谱 GLM](https://docs.bigmodel.cn/cn/guide/start/pricing)、[通义千问](https://help.aliyun.com/zh/model-studio/model-pricing)、[豆包方舟](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh)。

## 双入口与事实维护

人类入口是 [README](../README.md)，Agent 入口是 [SKILL.md](../skills/model-manual/SKILL.md)。两者共享事实与证据，只在导航和任务说明上区分；人类教程是按需查阅的辅助材料，不要求 Agent 顺序读取。

模型级机器事实保存在 [`skills/model-manual/references/models/`](../skills/model-manual/references/models/)；[`vendors.json`](../skills/model-manual/references/vendors.json)只负责厂商入口、默认型号和兼容摘要。型号的参数约束优先于厂商摘要，未知型号不能自动继承默认型号的思考开关。

| 内容 | 维护位置 | 其他入口怎么使用 |
|---|---|---|
| 准确型号的参数、能力与官方来源 | 型号机器卡片 | 生成器读取；人类说明书引用并解释，变更时同步相应文字 |
| 测试日期、范围与实际结果 | 原始脱敏报告 | 卡片指向报告；厂商能力摘要与验证状态页由同步脚本派生 |
| 默认型号及厂商入口 | vendors.json 的路由字段 | Agent 定位资料；默认型号之外按准确 ID 查卡片 |
| 接入、迁移、排错等项目工作流 | [Agent 任务流程](../skills/model-manual/references/workflows.md) | Skill 按任务路由，README 提供使用指令 |
| 官方功能示例的出处、改写与运行方式 | 每个型号的 `examples/sources.json` | [官方示例索引](官方示例索引.md)由清单生成，Agent 可按型号/能力查询 |

### 官方示例收录规则（项目规则）

基于官方文档写的代码标为 `adapted_from_official`，不称为官方原版；清单列出准确 Model ID、功能、官方页面、核对日期、必需环境变量、运行命令和项目改写。模拟数据、校验与循环上限属于项目补充，不当成厂商要求。厂商样例换成新型号时，先找当前收录型号的明确支持依据，不直接换名套用。

文件的 `verification.offline` 与 `verification.live` 分开记录。当前清单的线上状态全为 `not_run`，不沿用历史型号报告；离线 mock 只证明执行了模拟场景，不能证明真实 API 接受请求或模型结果可靠。未集成项列出原因与官方依据，不把“未写示例”和“模型不支持”混为一谈。清单新增文件/修改协议后更新相应测试，并运行 `example_catalog.py --write-index` 与 `--check`。

新增或更新型号身份、能力和通用参数时先修改准确型号卡片及来源，再更新受影响的示例和人类解释；具体功能示例的协议出处和改写记录维护在该型号的来源清单中，影响卡片已有结论时同时修正卡片。更新实测证据时新增报告、更新卡片指针，再运行同步脚本；不要手改派生能力摘要，也不要用编辑日期覆盖历史测试时间。模型说明书中的参数表目前不是自动生成的，维护时需检查它与卡片是否一致。

## 能力状态与验证证据

`verified`、`documented` 和 `unknown` 分别表示“仓库实测过”“官方文档说明但仓库未实测”和“没有可靠结论”。`unknown` 不等于不支持，只表示本项目不能据此下结论。

官方说明与实测结果分别记录：官方链接支持能力声明，报告支持具体运行结果。一次限流不会改写成“模型不支持”；一次请求被接受也不等于完整工具流程、输出边界或图片内容识别已经验证。

旧版报告只检查非空正文、首段工具参数或图片请求格式，保留为历史基础验证；没有记录的 `finish_reason` 和完整闭环结果不得补写成通过。新版本严格验证报告由脚本写出实际 SDK 版本、代码版本、安全参数、结束原因和分类结果；事实变化通过新增报告保留时间线。[历史报告示例](../models/kimi/kimi-k2.6/verification/2026-10-13.json)

本仓库要求 Python 3.10+，可复现环境使用[锁定依赖](../requirements-lock.txt)。正常安装、离线校验和真实 API 验证命令见[验证与复现](验证与复现.md)。
