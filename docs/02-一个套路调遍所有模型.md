# 02 · 一个套路调遍所有模型

这是整份指南**最重要的一章**。看懂它，你就掌握了 90% 的国产大模型调用方法。

---

## 核心事实：大家都在"抄" OpenAI 的作业

OpenAI 最早把"聊天接口"做成了一套标准格式，开发者都熟悉了。国内厂商为了让大家**零成本搬家**，纷纷把自己的接口做成了一模一样的格式，业内叫 **「OpenAI 兼容」**。

这意味着什么？

> 你用 OpenAI 官方的 `openai` 库写一份代码，**换个地址、换个模型名、换把钥匙，就能调用几乎所有国产模型。**

不需要为每家厂商单独学一个 SDK。

## 万能模板（背下来这一段）

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["API_KEY"],     # 钥匙：每家平台各自领一把
    base_url="____",                   # 地址：每家不一样
)

resp = client.chat.completions.create(
    model="____",                      # 菜名：每家的命名规则不一样
    messages=[                         # 你要说的话：格式家家都一样
        {"role": "user", "content": "你好"},
    ],
)
print(resp.choices[0].message.content)
```

真正会变的只有**三样东西**：`api_key`、`base_url`、`model`。其余代码一个字都不用改。

## messages 才是你真正要学的东西

既然换厂商只是改配置，那新手真正要花心思的，是怎么写好 `messages`。它是一个**按时间顺序排列的对话列表**，有三种角色：

| 角色 | 谁说的 | 用途 |
|---|---|---|
| `system` | 你给模型立的规矩 | 设定人设、回答风格、边界。可省略 |
| `user` | 用户 | 你问的问题 |
| `assistant` | 模型 | 模型之前的回答（多轮对话时由你回填） |

### 1）加人设：system

```python
messages=[
    {"role": "system", "content": "你是一个惜字如金的客服，每次回答不超过20个字。"},
    {"role": "user", "content": "请详细介绍一下量子计算的原理和应用前景"},
]
```

模型就会被"规矩"约束，尽量简短地回答。

### 2）多轮对话：把历史"原样还回去"

模型本身**不会**记住上一句。所谓"记得上下文"，是因为你每次都把之前的对话一起发过去：

```python
messages=[
    {"role": "user", "content": "我叫小明"},
    {"role": "assistant", "content": "你好小明！"},   # 上一轮模型的回答，要回填
    {"role": "user", "content": "我叫什么名字？"},      # 新问题
]
```

> 这是新手最常见的认知误区：**不是模型记性好，是你每次都把聊天记录重新发了一遍。** 完整可运行例子见 [`04_multi_turn.py`](../examples/04_multi_turn.py)。

### 3）流式输出：打字机效果

网页版聊天那种"一个字一个字蹦出来"的效果，只要加一个 `stream=True`：

```python
stream = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[{"role": "user", "content": "讲个30字的冷笑话"}],
    stream=True,                                        # 开启流式
)
for chunk in stream:
    print(chunk.choices[0].delta.content or "", end="", flush=True)
```

完整例子见 [`03_streaming.py`](../examples/03_streaming.py)。

## 两个常用但可以晚点学的参数

```python
client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[...],
    temperature=0.7,      # 0~2：越小越稳定/死板，越大越随机/有创意
    max_tokens=500,       # 限制回答最长多少 token，防止"写嗨了"烧钱
)
```

新手阶段记一个 `max_tokens` 就够用了——它能当"花钱保险丝"。

## 思考模式：五家实测对照（2026-10-13 ✅）

新一代模型默认会"先想再答"（推理模型）：更聪明，但**思考过程也按输出 token 计费**，且回答在 `reasoning_content` 字段里。实测结果：

| 厂商 / 模型 | 默认 | 关闭思考的写法（已实测生效） |
|---|---|---|
| DeepSeek `deepseek-v4-flash` | 开思考 | `extra_body={"thinking": {"type": "disabled"}}` |
| Kimi `kimi-k2.6` / `kimi-k3` | 开思考 | `extra_body={"thinking": {"type": "disabled"}}` |
| 智谱 `glm-4.7-flash`（免费） | **也开思考** | `extra_body={"thinking": {"type": "disabled"}}` |
| 豆包 `doubao-seed-2-1-pro` | 开思考 | `extra_body={"thinking": {"type": "disabled"}}` |
| 通义 `qwen3.6-flash` | 开思考 | **`extra_body={"enable_thinking": False}`（百炼独一份）** |
| 通义 `qwen-flash` | 不思考 | 无需设置 |

两个实测发现的坑：

1. **参数分两派**：DeepSeek/Kimi/智谱/豆包都是 `thinking.type`，只有百炼是 `enable_thinking`，抄错不报错但白写。
2. **智谱免费模型默认思考 + `max_tokens` 太小 = 回答空字符串**：思考链把额度吃光，`content` 返回 `''`。对策：关思考，或 `max_tokens >= 256`。

```python
# 四派通用关法
resp = client.chat.completions.create(
    model="deepseek-v4-flash",                 # 或 kimi-k2.6 / glm-4.7-flash / doubao-seed-2-1-pro
    messages=[{"role": "user", "content": "1+1=?"}],
    extra_body={"thinking": {"type": "disabled"}},
)
print(resp.choices[0].message.content)         # 思考链（若有）在 message.reasoning_content
```

新手不用纠结，**默认设置先跑通**，需要省钱/提速时回来关掉思考。

## 本章小结

1. 国产模型几乎都 **OpenAI 兼容**，一个 `openai` 库通吃；
2. 换厂商只改三样：**`api_key`、`base_url`、`model`**；
3. 真正要学的是怎么组织 `messages`：system 立规矩、多轮要回填历史；
4. `stream=True` 出打字机效果，`max_tokens` 当花钱保险丝。
