# 05 · 报错速查与安全规则

[English](../en/docs/troubleshooting.md)

错误码含义以厂商返回和官方文档为准；本页只给出项目采用的排查顺序，不把同一个 HTTP 状态码武断地归结为同一个原因。[核验规则](来源与核验规则.md)

## 先做四步

1. 保存完整状态码、错误类型、请求 ID 和错误文本，但删除 Key 与业务敏感内容；这是本项目的排查规则。[项目规则](来源与核验规则.md)
2. 用 [`examples/01_quickstart.py`](../examples/01_quickstart.py) 或生成器产出的最小代码复现，以区分账户/模型问题和业务代码问题。[生成器](../skills/model-manual/scripts/generate_snippet.py)
3. 回到对应厂商的官方接口、模型和价格页核对 `base_url`、模型名、开通状态与余额；链接集中在 [README 快速参数表](../README.md#快速参数表)。
4. 只有在配置了真实 Key 且接受可能计费时才运行 [`tests/verify_calls.py`](../tests/verify_calls.py)；脚本的实际请求范围以源码为准。

## 常见现象

| 现象 | 项目排查顺序 | 官方依据 |
|---|---|---|
| `401` / 鉴权失败 | 检查环境变量是否存在、Key 所属平台与地域，不回显 Key | [DeepSeek 错误码](https://api-docs.deepseek.com/quick_start/error_codes/) · [Kimi 错误说明](https://platform.kimi.com/docs/api/errors) |
| `402` / 余额不足 | 打开厂商控制台和官方价格页核对余额与计费状态 | [DeepSeek 价格](https://api-docs.deepseek.com/quick_start/pricing/) · [Kimi 价格](https://platform.kimi.com/docs/pricing/chat) |
| `404` / 模型不存在 | 在官方模型页复制当前 Model ID，并检查是否需要开通 | [Kimi 模型](https://platform.kimi.com/docs/models) · [豆包模型](https://docs.volcengine.com/docs/ark/model-list?lang=zh) · [豆包开通](https://docs.volcengine.com/docs/ark/activation-management?lang=zh) |
| `429` / 限流 | 读取错误体中的限制信息，降低并发并按服务规则重试 | [DeepSeek 错误码](https://api-docs.deepseek.com/quick_start/error_codes/) · [Kimi 错误说明](https://platform.kimi.com/docs/api/errors) |
| 上下文超限 | 缩短历史，或从官方模型页选择满足上下文要求的模型 | [Kimi 模型](https://platform.kimi.com/docs/models) · [通义模型](https://help.aliyun.com/zh/model-studio/getting-started/models) |
| 流式片段内容为空 | 代码使用 `delta.content or ""`，同时保留完整事件用于定位 | [Kimi 流式指南](https://platform.kimi.com/docs/guide/utilize-the-streaming-output-feature-of-kimi-api) |
| 正文为空但有思考内容 | 检查 `reasoning_content`、输出上限和该模型的思考规则 | [DeepSeek 思考](https://api-docs.deepseek.com/guides/thinking_mode/) · [智谱思考](https://docs.bigmodel.cn/cn/guide/capabilities/thinking) |

## Key 安全

本项目规定 Key 只从环境变量、被 [`.gitignore`](../.gitignore) 排除的项目 `.env`，或可选 [call-llm Skill](call-llm-skill.md) 在用户主目录创建的 `keyenv` 读取；代码、Issue、聊天、截图和日志中不保存完整 Key。[项目规则](来源与核验规则.md)

```bash
# 只检查是否设置，不输出真实值
test -n "$DEEPSEEK_API_KEY" && echo "已设置" || echo "未设置"
```

疑似泄露时，去对应厂商的 Key 管理页面删除并重建：[DeepSeek](https://platform.deepseek.com/api_keys)、[Kimi](https://platform.moonshot.cn/console/api-keys)、[智谱](https://bigmodel.cn/usercenter/apikeys)、[通义](https://bailian.console.aliyun.com/?apiKey=1#/api-key)、[豆包](https://console.volcengine.com/ark/region:ark+cn-beijing/apiKey)。

永久写入 shell 配置会让同一用户下的进程读取到该值；是否采用这种方式由使用者自己的安全边界决定。本项目支持被忽略的项目级 `.env`；跨项目复用可选用户主目录的 `keyenv`，通过包装命令只加载本次所需的厂商 Key。[项目规则](来源与核验规则.md) · [Skill 用法](call-llm-skill.md)
