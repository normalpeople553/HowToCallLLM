# Official-documentation example index

[中文](../../docs/官方示例索引.md) | English

These are project examples adapted from official documentation, not a vendor SDK or a verbatim mirror of official samples. Each manifest records the exact model, official sources, required environment variables, commands, adaptations, and file-level evidence.

## Usage

Install [requirements-lock.txt](../../requirements-lock.txt) from the repository root, then set the required key and inputs. Python examples share the locked environment. TypeScript runtime/SDK requirements are in [package.json](../../package.json); `npm ci` installs the locked SDK. The catalog's `npx tsx` command additionally uses tsx, while the file executor invokes Node directly; see [reproduction](verification.md). cURL examples need curl, bash, and Python. Images and videos are sent to the relevant vendor: use only material you are authorized to upload.

Read the [English model manuals](../../models/README.en.md) and parameter notes before calling a model. Query by capability without sending requests:

```bash
python skills/model-manual/scripts/example_catalog.py --vendor deepseek --capability vision
python skills/model-manual/scripts/example_catalog.py --model kimi-k2.6 --capability video_input
python skills/model-manual/scripts/example_catalog.py --write-index
python skills/model-manual/scripts/example_catalog.py --check
```

The machine-readable JSON remains in its canonical schema, including the original source metadata. Use `--model` alone to list capability keys. An unknown model or capability exits with code 2 and never falls back to another model; known models include available keys and relevant integration boundaries in the diagnostics. `or` in the environment column means either input is sufficient; the API key is always required. Optional variables are documented in the files.

## Evidence labels

- `mock_tested`: a fake SDK checks request construction, message history, and failure handling; it does not prove server acceptance or answer quality.
- `compile_checked`: syntax compilation only. `not_run`: that class of check has not run.
- `live=passed`: the example and support-file hashes match a real file-execution report, the process and the example's own checks succeeded, and Python / TypeScript / cURL recorded `real_httpx` / `real_fetch` / `real_curl`. The last request for the target model must succeed, finish normally, and return nonempty final text with no unresolved tools, business error, or telemetry failure. Streaming also needs `[DONE]` or a real transport EOF marker. Old process-only reports remain available but cannot establish canonical `passed` status.
- `passed` does not establish support for every parameter combination, semantic accuracy, visual recognition quality, or future availability. Read the model-specific parameter page.
- `failed`, `rate_limited`, and `timeout` are not passes. `missing_key`, `missing_input`, and `missing_runtime` mean execution prerequisites were missing.
- `live=not_run` has no online execution evidence for that file. Other states require a report with matching model, status, and current source/support hashes; the time is read from that report. [Historical workflow checks](verification-status.md) cannot substitute for file-level evidence. The complete repository release view is [example execution status](example-status.md).
